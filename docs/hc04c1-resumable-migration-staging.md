# HC-04-C1 — 대용량 이전용 비공개 분할 보존

- 소규모 원자적 이전의 기존 300행/512KiB 한도는 변경하지 않습니다. 대용량 경로는 별도입니다.
- 공동 공간 소유자만 빈 대상을 확인하고 이전 세션을 생성할 수 있습니다. 정의 최대 2,000개, 회차 최대 100,000개, 총 16MiB, 최대 2,048개 청크를 허용합니다. 청크는 100행/128KiB 이하입니다. 한도 초과는 자동 생략하지 않고 차단합니다.
- 세션 UUID·전체 fingerprint·청크별 fingerprint, 순차 index 및 누적 수량/바이트를 저장합니다. 연결 중단 후 서버 nextIndex부터 동일 청크로 재개하며, 기존 청크의 다른 내용은 덮어쓰지 않습니다.
- 청크는 Firestore Rules 기본 거부 경로에 보존합니다. 현재 소유자와 멤버십 및 빈 대상을 다시 확인하고, 전체 청크를 고정한 뒤 원본 manifest를 재구성하여 서버 독립 검증 및 SHA-256 비교를 실행합니다. 검증 성공 상태는 SEALED입니다.
- 전체 검증을 마쳐도 실제 chores/occurrences는 생성하지 않습니다. 공개/활성화 트랜잭션의 별도 설계가 필요합니다. 취소는 최대 50개 청크씩 삭제하고 마지막 청크 정리 후에만 세션을 제거합니다. 이전 세션과 새 세션의 UUID가 다릅니다.
- Node 단위 및 demo Firebase 통합 테스트: 301개 회차, 중단/재개, 순서·변조·중복 방지, 권한 박탈, private staging, 검증 및 취소.
- C2: Android 분할 전송·원본 백업 연동, 임시 데이터 만료/보존 정책 및 부분 공개 차단을 보장하는 활성화 경로, 실제 기기 중단 복구 검증. 운영 Firebase/Play 배포 없음.
