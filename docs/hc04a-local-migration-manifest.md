# HC-04-A — 로컬 전체 데이터 이전 사전 준비

## 구현
- 명시적 사용자 동작에서 기존 Room의 세 테이블을 readRows 트랜잭션으로 읽고, LocalHouseholdStore 설정을 확인합니다. 읽기 전용이며 로컬 DB, 인증, 운영 Firebase, Play 변경이 없습니다.
- 현재 서버 확인된 소유자와 빈 공동 공간에서만 이전 준비가 가능합니다. 모든 로컬 구성원·과거 완료 행위자·배정자를 서로 다른 현재 구성원 UID에 직접 연결합니다. 이름 자동 매칭이나 계정 병합을 하지 않습니다.
- 원본 집안일 ID를 안정적인 SHA-256 클라우드 정의 ID로 매핑하고, 기존 서버 회차 ID 공식으로 날짜별 회차 ID를 결정합니다. 원본 로컬 ID, 이름, 설명, 카테고리, 시각, 반복 규칙/요일/간격, 배정 순서, 생성/수정 시각, 완료·건너뛰기 기록 및 이유를 이전용 메모리 자료로 구성합니다.
- 구형 workloadPoints=0은 원래 값과 기존 정의 점수를 모두 남깁니다. 시작일이 없는 정의나 중복/고아 기록, 날짜·규칙 오류, 허용되지 않은 구성원은 자동 보정하지 않고 전체 계획을 차단합니다.
- 정렬 및 길이 구분 정규화 SHA-256으로 동일 자료를 식별합니다. 변경된 원본, 대상 공동 공간 또는 매핑은 다른 계획이 됩니다.
- Kotlin 단위 테스트와 개발 미리보기의 이전 대상 확인 UI를 제공합니다.

## 아직 하지 않는 작업
- 자료 전송, 서버 manifest 검증 및 분할 staging/원자적 publish, 용량 제한, 중단 복구, 원본의 별도 백업 및 실제 마이그레이션 실행.
- 이전 승인 시점에서 원본/대상/권한을 다시 읽고 digest를 재검증해야 합니다. 현재 화면의 검토 결과만으로 서버 쓰기를 시작하지 않습니다.
- 계정 삭제 및 구성원 표시명 정책, 두 기기 검증, 운영 Firebase와 Play 배포는 별도입니다.
