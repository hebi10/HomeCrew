# FIREBASE-05 — 다중 기기 데이터 동기화 기초 (Draft)

## 이번 브랜치의 구현

- 인증·멤버십 확인 후 서버 Callable로 클라우드 집안일 생성/수정. `revision` 일치 조건으로 다른 기기에서 먼저 수정했을 때 덮어쓰지 않고 충돌 응답.
- 회차 완료/취소는 Firebase UID를 실제 행위자로 저장하고 `requestId` 기반 중복 요청을 거부 또는 안전 재생. 서버 트랜잭션과 감사용 작업 기록 제공.
- Android Firestore 실시간 수신 Flow: 집안일/회차 컬렉션을 구독하고 캐시 여부를 표시. 로그아웃/권한 박탈 시 리스너 해제 및 오류 전파.
- 로컬 Room 자료의 클라우드 이전 전 **읽기 전용 사전 검사**: 구성원 이름 ↔ Firebase UID 일대일 매핑 누락/충돌을 확인합니다.
- 모든 Cloud 호출은 **명시적 사용자 동작 이후에만** 진입할 수 있는 별도 게이트웨이에 격리; 로컬 데이터 자동 업로드·삭제 없음.

## 아직 필요한 중요한 작업

1. Room 전체 집안일 정의·반복 규칙·회차·건너뛰기·완료 시간까지 보존하는 서버 데이터 마이그레이션 설계와 원자성/중단 복구. 현재 마이그레이션은 사전 검사만 제공.
2. 서버 반복 회차 생성, 중복 방지, 업무량 균형 배정, 권한 내 원본/회차 수정·삭제의 완전한 계약.
3. Flutter가 아니라 HomeCrew Compose UI의 클라우드/로컬 모드 선택, 공유 집 전환, 실시간 화면 모델, 오프라인 변경 큐·재연결 충돌 해결.
4. 두 실기기에서 동시 완료/오프라인/취소/탈퇴/권한 박탈/계정 삭제를 재현해 검증. 실제 Android QA, Firestore Emulator 통합 테스트.
5. FIREBASE-05가 도입한 클라우드 자료의 계정 삭제·보존/공동 집 소유권/멤버십/사용자 인덱스 삭제는 현재 PR #44의 Auth-only 삭제 코드만으로 안전하지 않습니다. 기능 완성 전 배포 금지.

## 배포 경계

코드와 단위 테스트만 작성하였으며 운영 Functions, Rules, Firestore, Google Play, GitHub Pages에는 배포하지 않았습니다. 이 브랜치는 FIREBASE-04에 종속되는 Draft이며 **실시간 공동 관리 완성이라고 간주할 수 없습니다.**

## 2026-11-17 보완
- 명시적으로 요청한 집안일·날짜의 단일 회차를 서버 트랜잭션에서 한 번만 생성하는 `ensureRemoteOccurrence` Callable을 추가합니다. 출석 기록은 아직 없는 회차에 대해 생성할 수 있습니다.
- 하루 날짜는 서울 기준이며 오늘부터 62일 이내에 한하여 신규 생성할 수 있습니다. 기록 보존/과거 이전 및 반복 일정 서버 자동 생성은 여전히 후속 구현입니다.
- 동일 집안일/날짜 재요청 시 SHA-256 기반 결정적 ID로 기존 회차를 반환하고 중복 생성하지 않습니다.
- 서버는 호출자 멤버십, 원본 집안일, 실제 배정자의 구성원 권한을 재검증합니다.
