# HC-04-C2a — 대용량 이전 공개·롤백 서버 기반

- SEALED된 자료를 소유자가 명시적 index 요청으로 100행 이하 단위 반영합니다. 첫 행과 같은 트랜잭션에서 household migrationPublishLock을 설정하고 마지막 행·영수증과 함께 제거합니다. Firestore Rules가 chores/occurrences의 get/list를 차단하며 기존 Callable의 일반 집안일/일정/완료/미래 회차 변경 및 소규모 이전도 lock을 확인합니다.
- 각 청크의 세션 UUID·digest·순서·현재 소유자·멤버십·문서 충돌을 확인합니다. 동시 요청과 동일 index 재생은 서버 상태에 따라 처리하며, 전체 완료 영수증이 있으면 동일 세션의 재요청은 기존 결과를 반환합니다.
- 멤버십 변경으로 진행이 막힌 경우 원래 매핑을 복구하거나 부분 공개를 롤백합니다. 롤백은 정확한 세션 태그와 revision=1의 숨겨진 문서만 역순으로 제거하고 마지막에 빈 대상 검증 후 lock을 해제합니다. 완료되어 공개된 자료는 롤백하지 않습니다.
- 완료 후 임시 청크만 별도 분할 정리하고 완료 영수증과 실제 데이터는 보존합니다. 롤백된 세션은 기존 취소 API로 청크 정리합니다.
- demo Firebase 검증에 301회차 부분 공개 금지, 다른 구성원/일반 쓰기 차단, 권한 박탈, 역순 롤백, 전체 공개, 재생 및 정리를 추가합니다.
- 주의: 운영 배포 시 Functions와 Rules의 일치가 필수입니다. 현재 Android는 공개 lock 동안 일반 집안일 화면을 열 수 없으므로 별도의 소유자 관리 화면/Android 분할 전송·복구·정리 연결을 마친 후에만 기능을 활성화해야 합니다. Android 대용량 연결, 만료·비용·운영/실기기 QA는 후속. 운영 Firebase/Play 배포 없음.

## Android 연결 (HC-04-C2b)
- 기존 원본 재검증/AtomicFile 백업 절차를 대용량까지 확대하고, 결정적 청크 계획 및 서버 nextIndex/누적 수량 검증 후 한 번에 최대 8개 청크를 보존합니다. 단일 청크 100행/보수적 100KiB, 총 15MiB의 클라이언트 안전 한도를 적용합니다(서버 한도 128KiB/16MiB).
- 별도 소유자 관리 화면에서 저장 상태, 전체 검증, 최대 8개 청크 반영, 부분 반영 롤백, 취소 및 정리를 명시적으로 확인합니다. 공개 잠금 중에도 진입 가능하도록 일반 집안일 구독과 분리합니다.
- 완료 영수증은 저장된 원본과 비교하며 실제 원본 DB를 변경하지 않습니다. 원본 변경/취소 후 다른 자료의 재이전, 임시 데이터 만료 및 외부 백업 정책은 후속. 프로세스 강제 종료/실기기 실제 이전 및 비용·운영 검증 필요. release/운영 Firebase 차단 유지.
