# HC-03-C1 — 완료 변경 요청 영속 보존

- 공동 집안일의 명시적 완료/취소 요청을 네트워크 전송 전에 Android 비공개 SharedPreferences에 동기 commit합니다. Firebase 프로젝트·UID·공동 공간 ID를 해시한 키로 분리합니다. 집안일 제목·이메일·인증 토큰은 저장하지 않습니다.
- 프로젝트/계정/공간별 미확정 요청을 하나씩 보관합니다. 다른 요청으로 덮어쓰지 않습니다. 프로세스 종료/다이얼로그 재진입 이후 동일 요청 ID, 원본 revision, 목표 상태를 복구합니다.
- 화면 진입만으로 자동 발송하지 않으며, 서버 확인된 snapshot 이후 사용자가 동일 요청을 다시 시도할 때만 네트워크를 호출합니다. 오프라인 캐시 및 신규 오프라인 편집은 여전히 차단합니다.
- 서버 응답 + 확인된 snapshot에 의해 변경 결과를 판단하거나 충돌/거부를 확인한 경우 정확한 요청만 제거합니다. 요청 보존/삭제 실패는 신규 변경 차단 및 저장 상태 재확인으로 처리합니다.
- 재시도 중단은 서버 변경 취소가 아님을 안내하고 최신 데이터를 다시 조회합니다.
- JUnit의 재생성·계정/공간/프로젝트 분리·디스크 실패·손상 검증과 API35 실제 저장소 객체 재생성 검증을 추가합니다. 물리 기기 프로세스 강제 종료 및 실제 두 계정 연결/재연결 QA는 별도입니다.
- HC-03-C2 반복 일정 서버 생성·배정 및 미래 회차 갱신은 별도 작업. HC-05/06에서 삭제·탈퇴 시 큐 데이터 정리 정책을 통합할 예정입니다.
- 운영 Firebase 및 release 기능 활성화·Play 업로드 없음.
