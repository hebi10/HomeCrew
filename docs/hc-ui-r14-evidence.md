# HC-UI-R14 — 최종 27페이지 검증 자료 수집

기준: Drive 화면별 디자인 제작 명세 v1.2 (2026-11-25), [상세 기획](https://docs.google.com/document/d/1QMyyRrFGWFSVRaeYM1VAlOGlav008wuCIGxb-Vmp1wo/edit), #73 병합 main 40e01a55a836363a4df13945493793d6d248bbf6, 별도 개발 중인 #74 공동 공간. 이전 PR의 캡처는 해당 SHA의 참고 자료일 뿐 최종 main 증거가 아니다.

## 수집 규칙
- 기존 수동 screenshot QA / 최종 5환경 device matrix의 계측·빌드·Firebase 초기화 검증은 유지하고, 동일 실행의 추가 출력만 정리한다. 3환경 중복 자동 실행을 추가하지 않는다.
- 실제 앱 경로 PNG(테스트 데이터 포함), FakeGateway fixture, 실패 진단 XML/PNG, 출처 미분류 파일을 구분한다. 실패 실행은 모두 진단으로 분류하고 정상 이미지 수에 넣지 않는다.
- manifest.json은 정확한 checkout SHA, 환경, 글꼴, 계측 종료 코드, 파일 SHA256, PNG 헤더의 가로/세로, P01~P27의 확보 여부를 기록한다. 같은 이름은 경로 해시로 보존하고 기존 폴더 재사용을 금지한다.
- P20의 소유자 설정 fixture는 공동 일정/작업 화면이 아니므로 관련 참고 자료로만 기록한다. P19/P21/P22/P25는 현재 대표 캡처 시나리오가 없다. P17/P18 fake 증거는 비운영 서버 검증을 대체할 수 없다. 모든 화면의 시각 검토는 pending으로 시작한다.
- 7장 최소 수집 기준은 정상 앱 경로 PNG만 포함하며 기존 instrumentation 실패/FirebaseBootstrap 확인을 유지한다. 27개 전부를 캡처했다는 의미가 아니다. 미수집·미비교 항목은 manifest에서 남겨 후속 테스트/비교를 진행한다.

## 최종 순서
1. #74 선별 UI QA 및 안전 병합, 남은 화면별 시나리오/비운영 Firebase 검증 보강.
2. 검증된 최종 main의 UI-R09 device matrix를 수동 1회 실행(29/35/36, 글꼴 160%, 태블릿). 명시적 배포 승인 없이 Play/서버 변경 금지.
3. manifest의 정확한 SHA와 검사 결과를 확인하고 Drive 검증 폴더에 원본과 27페이지 비교표를 저장. 라이트/다크, 상태별/접힘 및 실제 계정 검증은 증거가 있을 때만 완료 처리.
4. 미확인 화면 및 기능 차이는 별도 우선순위 수정·재검증. 시안이 통합 저해상도 이미지인 부분은 픽셀 일치율을 산정하지 않는다.
